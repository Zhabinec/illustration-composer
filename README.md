# Illustration Composer

Figma-плагин собирает композиции из существующих векторов библиотеки. Исходники копируются, остаются редактируемыми и не заменяются AI-изображениями.

## Запуск

Нужны Node.js, npm с поддержкой workspaces и Figma Desktop. Из корня проекта:

```powershell
npm install
npm run build -w @illustration-composer/core
npm run build -w @illustration-composer/figma-plugin
```

В Figma: **Plugins → Development → Import plugin from manifest…**, выбери `apps/figma-plugin/manifest.json`. Открой файл с исходной библиотекой, затем запусти **Illustration Composer** из Development.

Плагин ожидает страницу «Библиотека компонентов» с исходными группами и разделами S/L. Векторы не включены в репозиторий как новая нарисованная библиотека: они берутся из открытого исходного Figma-файла. Дополнительные предметы, варианты и палитры регистрируются в разделе «Библиотека». Палитры и история сохраняются в документе.

## Основные сценарии

- **По названиям:** введи «Монета, кошелёк, телефон». Доступно 1–8 предметов, первый — главный. Неизвестные и неоднозначные названия блокируют создание.
- **По метафоре / заголовку:** например, «Финансовая безопасность». Локальный подбор предлагает существующие предметы и объясняет выбор; состав можно изменить. Поддерживаются восемь тем библиотеки, свободное понимание любых метафор пока не реализовано.
- **Шаблоны:** сохрани выбранную векторную сцену из примеров, затем меняй предметы и общий масштаб с сохранением пропорций.
- **Палитры:** импортируй JSON-файл или вставь JSON. Схема сохраняется в Figma-файле и доступна обычным композициям и шаблонам.
- **SVG:** после создания нажми «Скачать выделенную композицию». Перед скачиванием выполняется проверка векторности и повторный импорт в Figma.

Перемещение, поворот, дублирование, удаление и порядок слоёв доступны штатными средствами Figma. В автоматической сборке фоновые предметы находятся позади main; при необходимости уменьшить второстепенный предмет требуется подтверждение.

## Проверки

Для каждого workspace доступны `typecheck`, `test` и `build`:

```powershell
npm run typecheck -w @illustration-composer/core
npm run test -w @illustration-composer/core
npm run build -w @illustration-composer/core
npm run typecheck -w @illustration-composer/figma-plugin
npm run test -w @illustration-composer/figma-plugin
npm run build -w @illustration-composer/figma-plugin
```

## Архитектура и границы

Core содержит предметы, варианты, правила выбора, компоновку и цвета без зависимости от Figma/DOM. Плагин сканирует библиотеку, хранит Registry в shared plugin data, клонирует векторы, перекрашивает копии и экспортирует их через Figma API. Палитра — самостоятельная сущность; её нельзя выбрать как предмет.

При разработке использован Codex для анализа, кода, тестов и проверки интерфейса. Подбор в самом плагине работает локально по семантическим профилям, без внешней LLM, API-ключа и генерации рисунков.

Проект ещё требует финальной приёмки остальных сценариев Registry, визуальной доводки 2–3 сдаваемых композиций, отдельной проверки всех шаблонов, демонстрации и проверки установки в чистом окружении. Подробный статус находится в архитектурном плане; перечисление функции здесь не заменяет ручную приёмку.
