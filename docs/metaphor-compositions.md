# Подбор по метафоре и заголовку

В «Композиция → По метафоре / заголовку» введи тему и нажми «Подобрать предметы». Плагин показывает темы и объяснения выбора, заполняет редактируемый список названий. Первый предмет — главный. После проверки состава можно выбрать формат, S/L, роль дополнительных предметов, палитру и создать сцену через существующие Row/Focus.

Примеры для исходной библиотеки:

| Заголовок | Главный предмет | Поддерживающие предметы |
| --- | --- | --- |
| Финансовая безопасность | Монета с замком | Кошелёк |
| Учёба и новые знания | Книга | Ручка, лампа |
| Идеи для команды | Пазлы | Лампа, ручка |
| Мобильная связь | Телефон | Наушники |
| Порядок в документах | Папка | Ручка |
| Музыка в пути | Наушники | Телефон |

Это локальный словарный подбор с весами смысловых связей, **не LLM и не универсальное понимание метафор**. Восемь тем распознаются по началам русских слов; каждому существующему предмету назначены связи с темами и объяснения. Сочетания тем влияют на суммарный рейтинг. Повторение слова не повышает рейтинг. Выбираются максимум три разных предмета; главный обязан иметь вариант main. Сеть, сервер и API-ключ не используются.

## Ответственности модулей

- `packages/core/src/semantic/local-semantic-selector.ts` — чистый подбор по переданным понятиям, профилям и актуальному каталогу; ничего не знает о Figma и исходных названиях библиотеки.
- `packages/core/src/semantic/semantic-selection.ts` — проверка ID, числа предметов, повторов, объяснений и наличия главного варианта. Неизвестный ID (в том числе ID палитры) блокирует весь результат.
- `apps/figma-plugin/src/library-semantics.ts` — данные конкретной библиотеки: смысловые связи со стабильными AssetId, без Figma nodeId.
- `apps/figma-plugin/src/metaphor-composition.ts` — применение профилей, проверка результата и сообщение UI.
- `code.ts` — маршрутизация запроса, актуальный Registry и существующий pipeline создания.
- `ui.html` — запрос, объяснения, исправление состава и проверка вариантов через уже существующий сценарий по названиям. Устаревшие ответы на предыдущий запрос игнорируются по requestId и тексту.

Сначала подбор возвращает ID существующих предметов и объяснения. UI подставляет их текущие названия для редактирования. Перед созданием имена и варианты повторно разрешаются по актуальному каталогу; неоднозначные имена блокируют создание. Размер и роль не выдумываются: работает прежняя проверка с предупреждением при замене S на доступный L или наоборот. Палитры не передаются в семантический каталог. Рендерер клонирует исходные векторы, профиль не может создать новый рисунок.

## Ограничения и расширение

Неизвестные темы, слишком длинный/пустой ввод и явные отрицания дают объяснение без случайной сцены. При неудаче прежний предложенный состав очищается. Смешанный запрос может быть распознан лишь частично; показанные темы и причины позволяют оценить результат до создания.

Новые зарегистрированные предметы доступны по названиям сразу, но не получают автоматически выдуманный смысл. Для семантического подбора им нужен профиль со стабильным AssetId. Пока нет редактора профилей, новые связи добавляются в `library-semantics.ts`. ID исходного предмета сохраняется при его переименовании; смысловые данные следует пересмотреть, если пользователь заменяет его другим по смыслу рисунком.

Для более свободного языка можно добавить другой источник `SemanticSuggestion[]`, сохранив проверку каталога и существующий pipeline. Решение о внешней LLM остаётся отдельным: нужны оценка качества и минимальный proxy с ключом вне плагина. Нынешний механизм не следует выдавать за такой AI.

Автоматический подбор слотов художественного шаблона, предметов декора и индивидуальных ролей каждого дополнительного объекта пока не реализован. Этот шаг закрывает ограниченный рабочий путь по заголовку; художественная доводка композиций и SVG-проверка остаются в плане.

## Проверки

Автоматически проверены ранжирование, составные темы, отсутствие выдуманных/пропавших ID, неизменность каталога, отрицания, неизвестные темы, main/background, повторение слов, некорректный семантический ответ и объяснения для шести разных заголовков.

В Figma 2026-11-04 вручную проверены: «Финансовая безопасность» → монета и кошелёк → создание Focus 1200×800 с двумя отдельными векторными группами; «Дракон на луне» → понятная ошибка, очистка предыдущего состава и блокировка создания. Остальные заголовки проверены автоматическими тестами, без отдельной визуальной приёмки каждой сцены.

Проверки обоих workspaces: typecheck, test и build проходят (Core — 91 тест, plugin — 46). JavaScript из UI проходит синтаксическую проверку.
