# Документные палитры и экспорт SVG

## Палитры

Импорт находится в отдельном разделе «Палитры». Можно выбрать JSON-файл до 16 КБ или вставить JSON вручную. [Пример](examples/azure-palette.json) содержит все цветовые роли; обязательны только `name`, `dark`, `medium`, `light`. Также поддерживается `{ "name": "Название", "colors": { ... } }`.

`palette-import.ts` проверяет формат через Core `resolvePalette`, нормализует цвета и проверяет название среди встроенных и документных палитр. При совпадении названия импорт отклоняется без перезаписи. ID из JSON игнорируется: назначается свободный `palette-json-N`, который не пересекается с палитрами и AssetId. Произвольный `sourceNodeId` из JSON тоже не принимается.

После успешной записи палитра выбирается для следующих обычных композиций и шаблонов. При ошибке записи состояние приложения не обновляется. После перезапуска сохранённая схема остаётся доступной; последнее выбранное значение UI отдельно не сохраняется.

Хранение использует существующий `FigmaRegistryStore` и shared plugin data документа, без сервера и обязательного manifest ID. Схема документа совместима с предыдущими записями: у палитры из Figma остаётся `sourceNodeId`, у JSON-палитры этого поля нет. История предметов и привязки исходников сохраняются вместе с палитрами. JSON-палитры не попадают в каталог предметов. Палитры из Figma по-прежнему исключаются из предметов и источников шаблонов.

## SVG

Нажми «Скачать выделенную композицию» под настройками обычной композиции или шаблона. После создания выделяется весь новый фрейм. Для другой сцены выдели её фрейм или группу целиком.

`figma-svg-export.ts` выполняет последовательные проверки:

1. Выделен ровно один непустой фрейм или группа. Узлы и заливки проходят существующую проверку векторного содержимого; растровые заливки и ресурсы палитр отклоняются.
2. Figma экспортирует `SVG`-байты с `contentsOnly: true`, `svgIdAttribute: true`, `svgSimplifyStroke: false`. Упрощение обводок отключено ради точности, ID слоёв включены для сохранения названий. См. [Figma ExportSettings](https://developers.figma.com/docs/plugins/api/ExportSettings/).
3. Байты читаются как UTF-8. Для встреченной в реальном экспорте ошибки кодирования ID исправляются только атрибуты ID и их внутренние ссылки, если их Latin-1-последовательность представляет корректный UTF-8. Учитываются числовые XML-сущности, которыми Figma записывает байты названий. Правильная кириллица и обычные Latin-1-имена не меняются. Геометрия и цвета этой операцией не затрагиваются.
4. Результат проверяется на векторную геометрию, растровые/внешние ресурсы и неподдерживаемые элементы. Это проверка собственного вывода Figma, а не универсальный санитайзер произвольного SVG.
5. SVG повторно импортируется через `createNodeFromSvg`. Проверяются векторное содержимое, наличие редактируемой геометрии и размер с допуском 0,1 px. Временный узел удаляется в `finally`.
6. Только после успешной проверки UI получает SVG и предлагает скачивание через Blob. Отмена системного диалога не определяется плагином, поэтому интерфейс сообщает «передан на скачивание».

Растрового запасного экспорта нет. Проверка повторного импорта подтверждает размер и наличие векторных элементов, но не доказывает пиксельную идентичность и сохранение всех специфичных свойств Figma. Внешний SVG-редактор может иначе представить обводки, маски и группы.

## Проверенный пример

[Финансовая безопасность — лазурная](examples/finance-azure.svg): монета и кошелёк из исходной библиотеки, Focus 1200×800, [лазурная палитра](examples/azure-palette.json). Файл содержит 222 path, 1 rect и 3 группы; растровых элементов нет. Внутренние группы предметов называются «Монета» и «Кошелек». Кошелёк содержит цвет `#C6EAF2` пользовательской палитры.

В Figma 2026-11-04 вручную проверены:

- сохранение палитры через вставку JSON, закрытие и повторный запуск плагина, наличие восстановленной палитры;
- выбор восстановленной палитры и создание отдельной сцены с перекрашенным кошельком;
- скачивание SVG и проверка обратным импортом: 1200×800, 223 векторных элемента;
- сохранённый файл отдельно разобран XML-парсером: размер, отсутствие image/feImage/foreignObject, наличие путей, групп и цвета палитры;
- нормализация кириллических ID в сохранённом примере выполнена той же функцией адаптера, проверены названия и неизменность геометрии. Исправление кодирования и внутренних ссылок также покрыто unit-тестами.

Автоматические проверки: Core — 91 тест, plugin — 75 тестов; typecheck и build обоих пакетов; синтаксическая проверка JavaScript UI. Конфликты палитр, повреждённые цвета, отсутствие источника у JSON-палитры, старые записи реестра, отказы SVG и очистка неудачного повторного импорта покрыты тестами. Импорт через системный выбор JSON-файла и экспорт всех художественных шаблонов отдельно вручную ещё не проверены.
