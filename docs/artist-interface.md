# Интерфейс для художника

Основной путь: открыть «Шаблоны», выбрать готовую сцену, заменить нужные предметы, выбрать палитру и нажать «Создать вариацию». Технические параметры не являются обязательным шагом.

## Разделы

- **Шаблоны:** вариации готовых авторских расстановок. Предпросмотр находится рядом с реальными предметами этой сцены. Кнопка создания закреплена внизу.
- **Композиция:** новая расстановка по названиям или теме. Подробность рисунка и расположение названы обычными словами; значения S/L и Focus/Row остаются внутренними параметрами.
- **Библиотека:** добавление предметов и их вариантов из Figma. Варианты и история раскрываются отдельно, nodeId не показываются в списке новых ресурсов.
- **Палитры:** цветовые образцы с выбором одним нажатием. Добавление из выделенного в Figma открывает существующий сценарий регистрации палитры. Импорт файла и ручной JSON спрятаны в дополнительных настройках.

Под вкладками меняются заголовок и короткое объяснение назначения выбранного раздела. Переход к палитрам и обратно сохраняет состав текущей вариации. Каталог шаблонов обновляется при изменении каталога предметов; простое переключение вкладок не пересоздаёт форму.

## Предметы и декор — только из выбранного шаблона

Предыдущая ошибка: любая верхнеуровневая GROUP/FRAME становилась сменным предметом. Служебные группы, в том числе десятки `Group N`, ошибочно получали подпись второстепенного предмета.

`getTemplateSlots` теперь исключает группы с пустыми и служебными именами вроде `Group`, `Group 123`, `Frame`, `Vector`. Они **не удаляются из изображения**: клонируется весь исходник. Неизвестный смысл не выдумывается; такие части сохраняются как в образце и не получают отдельный контрол замены. Настоящий безымянный предмет тоже останется фиксированным до явной смысловой разметки — автоматически считать любой Group предметом нельзя.

Число предметов не ограничено искусственно двумя: если в источнике три именованных предмета, показываются три. Если один — один. Индексы исходных слоёв сохраняются, исключение служебных групп не сдвигает адреса замен.

Именованный декор (`конфетти`, `confetti`, `декор`, `decor`) попадает в отдельный свёрнутый блок. Блок создаётся только при наличии такого декора в исходном шаблоне. Контролы существуют только для его реальных слотов. Добавления произвольного декора или дополнительных предметов в сценарии вариации нет.

Смена шаблона очищает прежние предметные и декоративные контролы. Варианты нового предмета доступны внутри «Вариант предмета» после выбора замены; для предмета с единственным вариантом дополнительный выбор не показывается. Сохранены авторские перекрытия и библиотечные роли main/background.

## Окно и состояния

Начальный размер — 520×740. Центральная часть прокручивается независимо от закреплённых навигации и панели действий. Размер меняется за нижний правый угол; для клавиатуры — фокус на ручке и клавиши стрелок. Допустимые размеры проверяются в plugin sandbox. Кнопка создания одна для текущего сценария; экспорт SVG — вторичное действие. При загрузке и создании кнопки блокируются существующим pipeline.

Применены семантические цвета Figma, единые поля и кнопки, заметный фокус, подписи и клавиатурная навигация вкладок. Уменьшенное движение учитывается через `prefers-reduced-motion`. В плагине остаётся существующий HTML/JS-интерфейс; перенос на новый React-стек в этот шаг не выполнялся.

## Навыки и источники решений

`ui-ux-pro-max` и `shadcn` уже были установлены. Добавлен официальный пользовательский навык Astryx и его CLI; навык доступен также в каталоге Codex. Навыки будут автоматически доступны в следующих сообщениях.

Источники: [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill), [shadcn skills](https://ui.shadcn.com/docs/skills), [Astryx CLI](https://astryx.atmeta.com/docs/cli). Из Astryx использованы рекомендации по одному основному действию, понятным подписям и состояниям кнопок. Компоненты React из этих библиотек не подключались к существующему HTML-плагину; их наличие как навыков не меняет стек приложения.

## Проверки

В Figma просмотрены новый экран шаблонов, объяснения разделов и цветовые карточки. В «Книга + Телефон» показаны ровно два предмета без блока декора; в «Телефон и пазлы — квадрат» показаны два предмета и один свёрнутый блок исходного конфетти. Проверен переход за палитрой и обратно без потери выбранного кошелька.

После этого из нового интерфейса создана мятная вариация с кошельком поверх книги: получены независимые векторы с авторской расстановкой. Изменение размера окна за нижний правый угол проверено в Figma; закреплённая кнопка создания и вкладки остаются доступны в уменьшенном окне.

Регрессионные тесты проверяют, что двадцать служебных групп не создают двадцать дополнительных предметов, один предмет не получает выдуманные дополнения и декор, исходники и индексы слоёв сохраняются. Это не автоматическая визуальная приёмка всех экранов и размеров окна.

Typecheck, test и build обоих workspaces проходят: Core — 91 тест, plugin — 86. JavaScript UI прошёл синтаксическую проверку; дублирующихся ID элементов нет. Изменение размера мышью проверено вручную; весь клавиатурный сценарий и тёмная тема отдельно не проходили полную приёмку.
