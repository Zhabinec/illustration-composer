# Веб-редактор Illustration Composer

Разработка ведётся в ветке `codex/web-app`. Это отдельный браузерный адаптер общего Core; Figma Plugin API в веб-приложении не используется.

Из корня репозитория:

```powershell
npm ci
npm run dev:web
```

Открыть http://127.0.0.1:4173. Команда `npm run build` создаёт статическую веб-сборку в `apps/web/dist`.

Публичная версия: https://illustration-composer-studio.oaken-cabin-1355.chatgpt.site — вход не требуется. Опубликована через Sites 20 ноября 2026 года. Идентификатор хостинга сохранён в `.openai/hosting.json`; при обновлении нужно использовать тот же проект. Проекты пользователей хранятся локально в их браузере, общей серверной базы нет. Известные ограничения переноса библиотеки перечислены ниже и сохраняются у опубликованной версии.

## Возможности

- Подбор существующих предметов по теме или названиям через общий Core. Подбор по теме локальный, без внешней LLM и API-ключей.
- Библиотека оригинальных SVG, декор и исходные композиции в отдельных вкладках.
- Перетаскивание, координаты X/Y, пропорциональный размер, поворот, замена рисунка и его S/L/main/background-варианта.
- Дублирование с сохранением редактирования, удаление, перестановка слоёв, отмена и повтор.
- Формат холста, фон, палитра и импорт палитры из JSON.
- SVG-экспорт независимых векторных групп, сохранение проекта в JSON и восстановление из браузерного хранилища.
- Импорт SVG-предмета и JSON-библиотеки, экспортированной плагином.

`src/model.ts` описывает сцену; `composition.ts` адаптирует предметы к Core; `svg.ts` проверяет и собирает векторы, разделяет идентификаторы копий и перекрашивает известные цвета; `storage.ts` проверяет проекты и работает с localStorage; `history.ts` хранит снимки сцены. `main.ts` связывает интерфейс и операции. Исходные SVG находятся в `src/library.json`.

Разметка рабочего окна находится в `src/workspace-view.ts`; швейцарский стиль задаётся в `src/styles.css`: Helvetica/Arial, строгая сетка, белый/чёрный и красный акцент. Цвета иллюстрации выбираются независимо от оформления интерфейса.

## Публикация на Render

В корне есть `render.yaml` для статического сайта из ветки `codex/web-app`. После отправки ветки в GitHub подключите этот репозиторий в Render через **New → Blueprint** и выберите указанную ветку. Платный сервер и переменные с секретами не требуются.

При ручном создании **Static Site** оставьте Root Directory пустой, задайте Build Command `npm ci --include=dev && npm run build -w @illustration-composer/core && npm run build -w @illustration-composer/web`, Publish Directory `apps/web/dist` и Node.js 24. Render выдаст адрес на `onrender.com`; собственный домен подключается отдельно. Ссылка на Render появится здесь после подтверждения успешного развёртывания.

## Проверки и оставшиеся ограничения

`npm run check` проверяет сборку, TypeScript и тесты трёх workspaces. Для веб-редактора добавлены проверки разрешения названий, подбора по теме, главного предмета с фоновым рисунком и отмены изменений.

В браузере проверены базовое отображение, подбор по теме, дублирование, изменение координат через кнопку применения, смена варианта, палитры и восстановление сцены после обновления.

Скачивание SVG пользователем ещё требует ручного подтверждения. Перенос декора и исходных шаблонов также требует повторной проверки: первоначальный JSON экспортировался с локальными размерами и поворотами Figma-узлов, тогда как SVG может уже содержать применённый поворот. Экспортёр плагина обновлён для использования SVG viewBox и границ отрисовки; включённую библиотеку необходимо повторно экспортировать этим вариантом и визуально сравнить с исходниками. Не считать точное совпадение шаблонов и декора подтверждённым.

Веб-версия пока не повторяет интерфейс регистрации альтернатив и конфликтов Figma Registry. Подключённая библиотека и ручная сборка доступны независимо от Figma, но публикация и завершение этих проверок ещё впереди.
